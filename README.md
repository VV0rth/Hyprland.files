# Linux Desktop & Dotfiles

Personal configuration for a CachyOS desktop centered on **Hyprland**, with a coordinated terminal, shell, editor, and desktop UI setup. The files here cover both day-to-day workflow and the visual details that tie the environment together.

> **Status:** This directory contains the configs described below. Adapt machine-specific paths, monitor names, packages, and commands before using it on another system.

## Desktop environment

### Hyprland

The Hyprland setup is organized as Lua modules under [`hypr/`](hypr/), with `hyprland.lua` loading the pieces. The configuration sets **Super** as the main modifier and separates behavior into focused modules:

- `hypr/config/` — animations, autostart, colors, decorations, defaults, environment, input, keybinds, monitor configuration, variables, and window rules.
- `hypr/dms/` — DankMaterialShell-related binds, colors, cursor, layout, outputs, and window rules.
- `hypr/hyprlock.lua` and `hypr/hyprlock.conf` — lock-screen configuration.
- `hypr/monitors.lua` and `hypr/workspaces.lua` — monitor and workspace helpers.
- `hypr/scripts/` — screenshot, area capture, and full-screen capture helpers.

The current monitor module names `DP-1` and `HDMI-A-1`, each at 3440×1440 and 100 Hz. The default applications include Kitty, Zen Browser, Nautilus, and Rofi. Keybinds cover launching apps, window focus and movement, floating/fullscreen/group operations, resizing, workspace navigation, media/volume, brightness, and screenshots. Autostart launches DMS, a volume OSD pipeline, the Polkit agent, session environment setup, idle handling, and Google Messages.

The Lua files are marked as generated by `hyprlang2lua`; review them alongside the installed Hyprland and Lua integration before changing or reloading the configuration. Some modules and commands rely on local packages and session services.

### Desktop shell: DankMaterialShell or Noctalia

The desktop shell is not the same across every machine: this setup uses **DankMaterialShell (DMS)** on some systems and **Noctalia** on others. The shell is selected per system, while Hyprland and the surrounding application configs provide the shared desktop foundation. This `.config` tree currently contains DMS/Quickshell-related files; it does not currently include a Noctalia-named config directory.

- [`quickshell/`](quickshell/) contains the Quickshell/DankMaterialShell source tree, including bar, dock, control center, notifications, lock screen, settings, and other desktop modules.
- [`hyprpanel/`](hyprpanel/) contains a separate HyprPanel configuration and module preferences.
- [`DankMaterialShell/`](DankMaterialShell/) contains local DMS themes and plugins.
- [`matugen/`](matugen/) contains templates used to generate coordinated colors for Hyprland and other applications.

These folders include substantial application or upstream source/config content. DMS-specific startup entries and integrations apply only on systems where DMS is the selected shell; adapt them when using Noctalia.

## Terminal, shell, and editor

### Kitty

[`kitty/kitty.conf`](kitty/kitty.conf) uses **JetBrains Mono Nerd Font** at 11 pt, a translucent background, a beam cursor with trail, and a powerline tab bar. It starts Fish, adds custom copy/interrupt behavior, provides search bindings, and maps keys for scrolling and font-size changes. Theme and tab styling live in `kitty/dank-theme.conf` and `kitty/dank-tabs.conf`; `scroll_mark.py` and `search.py` are helper scripts.

### Fish and Starship

[`fish/config.fish`](fish/config.fish) sources CachyOS's Fish configuration, conditionally loads Pywal colors, adds local tool directories to `PATH`, and initializes Drift. Personal functions are in `fish/functions/` and completions in `fish/completions/`.

[`starship.toml`](starship.toml) defines a compact, color-segmented prompt using environment-provided colors. It includes OS, username, directory, Git state, command duration, and language/tool symbols. Fish's Starship initialization is currently commented out in `config.fish`.

### Neovim

The [`nvim/`](nvim/) directory is a **LazyVim starter configuration** bootstrapped through `lazy.nvim`:

- `init.lua` loads `config.lazy`.
- `lua/config/` contains plugin bootstrap, options, keymaps, and autocommands.
- `lua/plugins/` contains colorscheme and transparency overrides, Dank colors, and the example plugin file.
- `colors/` and `lua/lualine/themes/` provide custom DMS color integrations.
- `lazy-lock.json` records plugin revisions; `stylua.toml` configures Lua formatting.

Tokyo Night is configured with transparency enabled. Lazy.nvim checks for plugin updates periodically without notifications and disables a few built-in runtime plugins.

### Alacritty and tmux

[`alacritty/`](alacritty/) contains a second terminal configuration. [`tmux/tmux.conf`](tmux/tmux.conf) enables mouse support and uses a transparent/default status background.

## Documents and system appearance

### Zathura

[`zathura/zathurarc`](zathura/zathurarc) enables recoloring, transparent page backgrounds, and adjusts opened documents to fit the window width.

### GTK and Qt

- `gtk-3.0/` and `gtk-4.0/` — GTK appearance preferences; GTK4 currently prefers a dark theme, Fira Sans, and Capitaine cursors.
- `qt5ct/`, `qt6ct/`, `Kvantum/`, and `qt5ct/colors/` — Qt appearance and theme settings.
- `environment.d/` and `xdg-desktop-portal/` — session environment and portal preferences.

### Other configured applications

Additional folders include `btop/` (system monitor), `fuzzel/` (launcher), `fcitx5/` (input method), `wireplumber/` (audio), `ncspot/` (terminal music client), `vlc/`, and various application-specific settings. Their presence can vary over time; browse the folders for the current options.

## Portability notes

- Review monitor names and resolutions in `hypr/` for your hardware.
- Several commands, paths, and startup services are specific to this machine or CachyOS; install the corresponding programs or adjust those entries first.
- Colors are shared/generated across applications. Look at `matugen/`, `hypr/`, and Kitty theme files when changing the palette.
- Runtime state and caches are not useful dotfiles. Keep browser profiles, databases, logs, and other machine-generated state out of a public repository.
